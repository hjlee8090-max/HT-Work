> 실행 규칙은 00-orchestrator.md 참조. 아래 내용은 v0.6 원본에서 무수정 추출했다.

## 1. 목적, 성공 기준, 비목표

### 1.1 목적

로컬 프로젝트에서 LLM 작업을 "티켓" 단위로 **계획 → 승인 → 실행 → 보고**하고, 일 단위 메모리로 세션 간 맥락을 유지하는 Claude Code / Cowork 플러그인을 만든다.

핵심 가치는 2가지다.

- **통제**: 사용자가 승인한 티켓만 실행된다. 같은 티켓을 두 번 실행하지 않는다.
- **연속성**: `/done` 한 번으로 하루가 기록되고, 오래된 기록은 자동 압축되어 다음 세션의 맥락이 된다.

### 1.2 성공 기준 (v1 완료 판정)

| # | 기준 | 검증 |
|---|------|------|
| S1 | init → tickets → 승인 → run → 리포트 → done 루프가 데모 프로젝트에서 끝까지 동작 | §6 시나리오 A |
| S2 | 미승인 티켓 실행 0건, 동일 티켓 중복 실행 0건 | §6 시나리오 B |

| S7 | 모든 suggested 티켓의 purpose에 §4.7 출처 태그와 근거가 있고, 정의된 출처 밖 일반론 제안이 0건 | §6 시나리오 E |

멀티유저 협업 · 원격 동기화 · GitHub 이슈 연동 · 로컬 웹서버 구동 · 드래그앤드롭 정렬 · 자동 스케줄링(cron) · 통계 대시보드. 필요해지면 §7 Open Issues로만 기록한다.

### 부록 A — 각 SKILL.md 프론트매터 초안

description은 "무엇을 하는지 + 언제 트리거되는지"를 모두 담고 다소 적극적으로 쓴다 (스킬은 과소 트리거 경향이 있음). 아래는 초안이며 구현 시 다듬는다.

- **project-setup**: 프로젝트 초기 세팅 스킬. "프로젝트 세팅", ":init", "티켓 파일럿 시작" 요청 시 반드시 사용. 프로젝트 스캔, 기존 스킬 인벤토리 수집과 충돌 보고, CLAUDE.md 관리 블록과 .ticket-pilot 워크스페이스 생성까지 수행한다.
- **ticket-create**: 작업 티켓 초안 생성과 보드 HTML 재생성 스킬. "티켓 만들어줘/추가해줘", "보드 변경 반영해줘" 요청 시 반드시 사용. 연계 제안은 §4.7 파이프라인(출처 티어 · 필터 · 근거 명시)으로 최대 3건까지 제안하며, 업무 프로필(§4.6)의 규칙을 적용하고 인용한다. 보드·채팅 반영 처리 시 관찰을 프로필에 기록한다.
- **ticket-run**: 승인된 티켓의 순차 실행 스킬. "티켓 확인해줘/실행해줘", ":run" 시 반드시 사용. 승인·의존성·중복 방지 프로토콜을 따르며 티켓 범위 밖 작업을 하지 않는다.
- **ticket-optimize**: 완료 티켓 정리와 후속 티켓 제안 스킬. ticket-run 종료 시 자동 호출된다.
- **day-close**: 하루 마감 스킬. ":done", "오늘 마감해줘" 시 사용. RECENT_MEMORY 기록, memory-optimize 호출, 프로필 규칙 승격 보고와 소통 규칙(C-xx)의 CLAUDE.md 동기화, 반복 패턴 스킬 제안까지 수행한다.
- **memory-optimize**: 메모리 3계층 압축 스킬. day-close에서 자동 호출되며 "메모리 정리해줘" 단독 요청에도 응답한다.
