# 30 — E2E 테스트 시나리오 A~F (구축 실행 세트 v0.6-exec)
> 각 Phase의 DoD 검증과 Phase 5 전체 검증에서 사용한다.

## 6. E2E 테스트 시나리오

**시나리오 A — 기본 루프**
1. 데모 프로젝트에서 `:init` → CLAUDE.md 블록·워크스페이스 생성 확인
2. "회원가입 폼 만들기 티켓 생성해줘" → user 1건 + suggested 3건 이하 draft 확인
3. board.html에서 2건 승인, 1건 반려, 1건 문구 수정
4. "보드 변경 반영해줘" (클립보드 경로) → tickets.json 반영 확인
5. "티켓 확인해줘" → 승인 2건만 우선순위 순으로 실행
6. 리포트 탭에서 수행 요약·변경 파일·증빙 확인

**시나리오 B — 중복·통제**
1. run 도중 세션 강제 종료 → 재시작 → in_progress 감지·질의 확인
2. 재개 선택 → 이어서 완료. 파일 변경에 중복 없음 확인
3. done 티켓에 "다시 실행해줘" → 재오픈 절차 없이는 거부 확인
4. draft 티켓 실행 요청 → 거부 확인

**시나리오 C — 메모리·패턴**
1. RECENT에 날짜를 조작한 10일치 더미 엔트리 준비 → `:done` → 7일 초과분이 MIDDLE로 이동
2. MIDDLE에 35일 전 더미 섹션 → `:done` → LONG 병합 확인
3. 같은 날 `:done` 2회 → 당일 엔트리 중복 없음
4. "매일 아침 브리핑 정리" 요청을 3일치 메모리에 심기 → `:done` → 스킬 제안 발생, 승인 전 파일 미생성 확인

**시나리오 D — 개인화**
1. 프로필이 빈 상태에서 첫 ticket-create → 시드 절차(지식파일 참조 제안 또는 3문항 이내 질문) 발생 확인
2. suggested 배포 계열 3건을 서로 다른 날짜로 반려 → 관찰 로그 3건 기록 확인
3. `:done` → 규칙(R-xx) 승격과 근거 포함 보고 확인
4. 다음 ticket-create → 해당 계열 제안 제외 + "R-xx에 따라" 인용 확인
5. "R-xx 거부" → 취소선 보존 확인, 다음 생성에서 해당 제안 부활 및 동일 규칙 재승격 시 사용자 확인 요구
6. "앞으로 문서화 제안은 항상 포함해줘" 명시 지시 → 임계 없이 즉시 규칙 기록 확인 (D-25)
7. 활성 R-xx가 제외하는 계열의 티켓을 서로 다른 날 3회 직접 생성 → `:done`에서 규칙 재검토 제안 확인, 자동 해제 없음 확인 (D-26)

**시나리오 E — 제안 품질**
1. 메모리 "미해결"에 항목 1건, done 티켓 followup 1건, blocked 티켓 1건을 심고 ticket-create → 제안 3건이 티어 순서로 나오고 각 purpose에 출처 태그 확인
2. 출처 없는 일반론(예: "테스트 커버리지 개선")이 제안에 포함되지 않음 확인 (F5)
3. 반려했던 티켓과 실질 동일한 제안이 다시 나오지 않음 확인 (F2)
4. suggested 반려를 누적해 최근 10건 승인율을 1/3 미만으로 → 다음 생성에서 제안 상한 1건 적용 + day-close 보고 확인

**시나리오 F — 소통 톤 학습**
1. init 직후 CLAUDE.md 관리 블록에 소통 방식 기본값이 존재하는지 확인
2. 서로 다른 날 3회 용어 재설명을 요청 → 관찰 로그 3건 기록 확인
3. `:done` → C-xx 승격 보고 + CLAUDE.md 소통 방식 절 갱신 확인 (블록 60줄 이하 유지)
4. 다음 세션의 티켓 purpose·실행 보고에서 약어에 한 줄 풀이가 붙는지 확인
5. "C-xx 거부" → CLAUDE.md에서 제거 + profile.md 취소선 확인
6. 작업 지시 문구를 소통 규칙으로 승격 시도(테스트) → 동기화 거부 확인
