# day-close — 하루 마감

## 목적

`/tp:done` 한 번으로 하루를 기록하고 다음 세션의 맥락을 만든다: 오늘 엔트리 기록 → 메모리 압축 → 프로필 규칙 승격 → 소통 규칙 CLAUDE.md 동기화 → 제안 신뢰 예산 점검 → 반복 패턴 스킬 제안.

## 입력

- `.ticket-pilot/tickets.json` (오늘 done·blocked 티켓), `.ticket-pilot/memory/` 3파일, `.ticket-pilot/profile.md`, CLAUDE.md
- `.ticket-pilot/journal.ndjson` (변경 저널 — 없으면 부트스트랩 1줄로 만든다)
- 없는 파일이 있으면 "/tp:init 먼저"를 안내하고 중단

## 안전 저장 (memory·profile·CLAUDE.md 쓰기에 예외 없이 적용)

여러 세션이 같은 프로젝트를 동시에 열 수 있다. 이 스킬이 쓰는 파일은 티켓 ID 같은 단위가 없으므로 **절 단위**로 지킨다. 전체 규약은 `${CLAUDE_PLUGIN_ROOT}/references/safe-write.md`.

1. **재읽기**: 쓰기 직전 파일을 다시 읽는다.
2. **재적용**: 내가 읽은 뒤 내용이 달라졌으면 — 다른 세션이 썼다 — 내 편집을 **현재 파일 위에 다시 적용**한다. 들고 있던 사본으로 덮어쓰지 않는다. 재적용했으면 보고에 1줄 남긴다.
3. **축소 금지**: 결과가 현재 파일보다 짧아지는데 그게 2절의 의도한 압축이 아니면 **저장하지 않고** 보고한다.
4. **"같은 내용이라 덮어썼다"는 판단을 하지 않는다** — 같은 내용이면 쓸 이유도 없다. 이 판단이 가드를 무력화하는 가장 흔한 경로다.
5. **저널 기록**: 저장 후 `.ticket-pilot/journal.ndjson`에 파일당 1줄 덧붙인다(append만):
   `{"at":"<ISO8601>","session":"<세션 4자리 ID>","actor":"day-close","op":"write","file":"profile.md","note":"R-05 승격"}`

## 실행 단계 (순서 엄수)

### 0. 인계장 흡수 (있을 때만)

`.ticket-pilot/HANDOFF.md`가 존재하고 상태가 "대기"(소비 안 됨)면 — 세션 인계 후 재개 없이 하루를 마감하는 상황이다:
- 인계장의 "지금 하던 일"·"미반영 결정"·"사용자 답변 대기"를 1단계의 오늘 엔트리(미해결/이슈 · 내일 후보)에 흡수한다.
- 인계장 상단 상태를 `소비됨 (마감 흡수: {시각})`으로 바꿔 저장한다.

### 1. 오늘 엔트리 기록

오늘 완료 티켓(result.summary 1줄씩)·결정·이슈를 아래 템플릿으로 `RECENT_MEMORY.md` **최상단**(헤더 바로 아래)에 추가한다:

```markdown
## 2026-07-23 (수)
### 완료
- T-003 회원가입 저장 처리 — 결과 요약 1줄
### 결정
- (없으면 섹션 자체를 생략)
### 미해결 / 이슈
- …
### 내일 후보
- …
```

- **당일 엔트리가 이미 있으면 병합한다. 같은 날짜의 엔트리를 두 개 만들지 않는다.** 병합 시 기존 항목과 중복되는 줄은 넣지 않는다.
- 완료 티켓 항목은 `T-xxx 제목 — 요약 1줄` 형식. blocked 티켓은 "미해결 / 이슈"에 사유·재개 조건과 함께 적는다.
- 대화에서 내려진 결정(방향 선택, 정책 확정)은 "결정"에, 다음에 할 일 후보는 "내일 후보"에 적는다.

### 2. 메모리 압축 (3계층 · 기준일은 오늘)

| 파일 | 담는 것 | 단위 |
|------|---------|------|
| RECENT_MEMORY.md | 최근 7일 | 일 단위 엔트리 (`## YYYY-MM-DD (요일)`) |
| MIDDLE_MEMORY.md | 7~30일 | 주 단위 요약 (`## YYYY-MM-DD~MM-DD 주`) |
| LONG_MEMORY.md | 30일 초과 | 월 단위 핵심 (`## YYYY-MM`) |

압축 규칙 (순서 엄수 · 원문 복구는 git 히스토리로):
1. **RECENT → MIDDLE**: 날짜가 **7일 초과**한 일 엔트리들을 같은 주(월~일) 단위 1개 섹션(`## 2026-07-13~07-19 주`)으로 요약해 MIDDLE **상단**에 추가하고 RECENT에서 제거한다. 요약은 원문의 **1/4 이하** — 완료 티켓 ID는 유지하고, 지금도 의미 있는 결정·미해결만 남긴다.
2. **MIDDLE → LONG**: **30일 초과**한 주 섹션들을 월 단위로 LONG의 해당 월 섹션(`## 2026-06`)에 병합하고 MIDDLE에서 제거한다. **지금도 유효한 결정과 프로젝트 궤적만** 1~2문단으로 남긴다.
3. **LONG 보호**: LONG은 자동 삭제하지 않는다. 300줄을 넘으면 사용자에게 정리를 **제안만** 한다.
4. 결과를 "이동 n건, RECENT x줄 → y줄" 형식으로 마감 보고에 포함한다.
5. **저널 회전**: `journal.ndjson`이 1000줄을 넘으면 **가장 오래된 500줄을 `journal.<YYYY-MM>.ndjson`으로 옮긴다.** 지우지 않는다 — 옮긴 파일도 저장소에 남는다. 옮긴 뒤 현재 저널 첫 줄에 `op:"bootstrap"`(+현재 tickets.json의 전체 ID 목록)을 새로 써서 대조 기준선을 유지한다. 1000줄 이하면 아무것도 하지 않는다.

**압축만 모드**: "메모리 정리해줘" 단독 요청이면 이 절만 실행하고 결과를 보고한다 — 오늘 엔트리 기록(1)과 이후 단계(3~6)는 생략한다.

### 3. 프로필 승격 검토

profile.md의 "관찰 로그"를 유형별로 묶어 검토한다:

1. **승격 임계**: 동일 유형 관찰이 **3회 이상이고 2일 이상**에 걸쳐 있으면 승격한다. 하루치 몰아친 관찰만으로는 승격하지 않는다(과적합 방지). 임계 근처(2회)면 "패턴(승격 대기 후보)" 절에 올린다.
2. **분류**: 티켓 생성·선별·크기에 관한 것은 작업 규칙 **R-xx**, 표현·설명 방식에 관한 것은 소통 규칙 **C-xx**. 번호는 기존 최대 번호+1.
3. **근거 인용 의무**: 규칙에는 반드시 근거(날짜·티켓 ID·발화 인용)를 붙인다. 근거 없는 규칙은 만들지 않는다. 승격이 끝난 관찰은 로그에서 지우고 규칙의 근거 요약으로만 남긴다.
4. **보고와 거부권**: 신규·변경된 규칙을 근거와 함께 마감 보고에 표로 알린다. 사용자가 거부하면 취소선으로 보존한다 (`~~R-04 …~~ 거부 7/23`). **거부된 규칙은 자동 재승격하지 않으며**, 같은 유형 관찰이 다시 쌓여도 사용자 확인을 거쳐서만 재승격한다.
5. **반례 재검토**: 활성 규칙과 모순되는 관찰(반례)이 3회 이상 · 2일 이상 쌓인 규칙은 재검토를 제안한다. **자동 해제는 금지** — 해제는 사용자 결정으로만. 재검토 결과 사용자가 "유지"를 택하면 해당 반례 관찰에 `→ 재검토 완료(유지 날짜)`를 표시해 다음 재검토 집계에서 제외한다. 표시 이후 **새** 반례가 다시 3회·2일 쌓이면 다시 제안한다.
6. profile.md가 100줄을 넘으면 승격이 끝난 관찰부터 정리한다. "마지막 갱신" 날짜를 오늘로 바꾼다.

### 4. 소통 규칙(C-xx) CLAUDE.md 동기화

C-xx가 새로 생기거나 바뀌었으면 CLAUDE.md의 ticket-pilot 관리 블록 안 **'소통 방식' 절만** 갱신한다:

- 기본값 3줄 아래에 `{C-xx 규칙 1줄 — 근거 요약}` 형식으로 추가한다.
- **표현 한정 검증**: C-xx는 표현·설명 방식만 규정할 수 있다. 작업이나 실행을 지시하는 문구("실행 전 테스트를 돌린다" 류)는 **동기화를 거부**하고 사유를 보고한다 — 그런 내용은 R-xx(작업 규칙)로 분류한다.
- 마커(`<!-- ticket-pilot:begin -->` ~ `end`) 밖은 절대 건드리지 않는다. day-close는 블록 안에서도 '소통 방식' 절 외에는 수정하지 않는다.
- '소통 방식' 절은 12줄 이하, 블록 전체는 60줄 이하를 유지한다. 초과하면 오래된 C-xx의 근거 요약부터 줄인다.
- 사용자가 C-xx를 거부하면 CLAUDE.md에서 해당 줄을 즉시 제거하고 profile.md에 취소선으로 보존한다.

### 5. 제안 신뢰 예산 점검

tickets.json에서 origin=suggested이고 결정이 끝난(승인 계열 approved·in_progress·done / 반려 rejected) 최근 10건의 승인율을 계산한다:
- 승인율 = 승인 계열 / (승인 계열 + 반려)
- 1/3 미만이면: "다음 티켓 생성부터 연계 제안 상한이 3→1건으로 줄어든다"고 보고한다.
- 이전에 상한 1이었다가 1/3 이상으로 회복했으면 "상한 3건 복원"을 보고한다.
- 결정된 suggested가 없으면 이 점검은 건너뛴다.
- 이 상태는 **보고만 한다** — profile.md 등에 별도 저장하지 않는다. 티켓 생성(ticket-create A-4)과 후속 제안(ticket-run 마무리) 시점에 tickets.json에서 각각 다시 계산되므로 저장하면 불일치만 생긴다.

### 6. 반복 패턴 → 스킬 제안

RECENT + MIDDLE 메모리에서 **같은 유형의 요청·작업이 3회 이상, 2일 이상**에 걸쳐 등장하면 스킬화를 제안한다:

- 판정 근거로 해당 메모리 엔트리 3건을 인용해 제시한다.
- 제안 형식: 스킬명 · 트리거 문구 · 입력→출력 · SKILL.md 초안 (대화에 초안 전문 표시).
- **사용자가 승인할 때만** `<프로젝트>/.claude/skills/<스킬명>/SKILL.md`를 생성한다. 승인 전에는 어떤 파일도 만들지 않는다.
- 생성 전 기존 스킬 인벤토리(프로젝트·사용자·플러그인 스킬)와 이름·트리거 충돌을 검사하고, 충돌하면 이름 변경을 제안한다.

### 7. 마감 보고

한 번에 보고한다: ① 오늘 엔트리 요약 ② 압축 결과 ③ 승격·변경 규칙 표(근거 포함) ④ C-xx 동기화 내역 ⑤ 신뢰 예산 상태 ⑥ 스킬 제안 (있을 때만) ⑦ 내일 후보 ⑧ 세션 활동.

**⑧ 세션 활동**: 오늘 날짜의 저널 줄을 `session`별로 묶어 보고한다 — 세션 수, 세션별 변경 건수, **내 세션이 아닌 세션이 있었으면 무엇을 바꿨는지 1줄씩**. 저널 회전이 일어났으면 그 사실도 적는다. 하루 동안 어느 세션이 무엇을 건드렸는지가 여기서 한눈에 보이게 하는 것이 목적이다. 오늘 저널 줄이 내 세션 것뿐이면 "단일 세션" 한 줄로 줄인다.

## 완료 기준

- [ ] RECENT_MEMORY 최상단에 오늘 엔트리가 정확히 1개 있다 (재실행 시 병합됨 · 압축만 모드는 해당 없음)
- [ ] 압축 후 RECENT에 7일 초과 엔트리·MIDDLE에 30일 초과 섹션이 없고, LONG은 병합만 되었으며, 이동·줄수 변화가 보고되었다
- [ ] 승격/거부/반례 처리가 근거와 함께 보고되었고, profile.md가 100줄 이하다
- [ ] C-xx 동기화 후에도 CLAUDE.md 블록 60줄 이하 · 소통 방식 절 12줄 이하 · 마커 밖 무변경이다
- [ ] 스킬 제안이 있었다면 승인 전 파일 미생성 상태다
- [ ] 대기 상태 HANDOFF.md가 있었다면 오늘 엔트리에 흡수되고 소비됨으로 마킹되었다
- [ ] 모든 쓰기가 "안전 저장"을 거쳤다 — 쓰기 직전 재읽기, 다른 세션 변경이 있었으면 현재 파일 위에 재적용·보고 (사본 덮어쓰기 없음)
- [ ] 쓴 파일마다 journal.ndjson에 1줄이 덧붙었고, 1000줄 초과였다면 회전이 수행되었다
- [ ] 마감 보고에 세션 활동(⑧)이 포함되었다
