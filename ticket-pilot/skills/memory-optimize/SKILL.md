# memory-optimize — 메모리 3계층 압축

## 목적

`.ticket-pilot/memory/`의 3계층을 압축해 오래된 기록이 다음 세션의 맥락을 압박하지 않게 한다. 원문 복구는 git 히스토리로 한다(메모리 파일은 커밋 대상).

| 파일 | 담는 것 | 단위 |
|------|---------|------|
| RECENT_MEMORY.md | 최근 7일 | 일 단위 엔트리 (`## YYYY-MM-DD (요일)`) |
| MIDDLE_MEMORY.md | 7~30일 | 주 단위 요약 (`## YYYY-MM-DD~MM-DD 주`) |
| LONG_MEMORY.md | 30일 초과 | 월 단위 핵심 (`## YYYY-MM`) |

## 압축 규칙 (순서 엄수)

기준일은 오늘이다. day-close가 호출한 경우 오늘 엔트리는 이미 RECENT 상단에 있다.

1. **RECENT → MIDDLE**: RECENT에서 날짜가 **7일 초과**한 일 엔트리들을 모아 **주 단위 1개 섹션**으로 요약해 MIDDLE **상단**에 추가하고, RECENT에서 제거한다.
   - 요약 분량은 원문의 **1/4 이하**. 완료 티켓 ID는 유지하고, 지금도 의미 있는 결정·미해결만 남긴다.
   - 같은 주(월~일)에 속하는 엔트리는 한 섹션으로 묶는다. 섹션 제목: `## 2026-07-13~07-19 주`
2. **MIDDLE → LONG**: MIDDLE에서 **30일 초과**한 주 섹션들을 **월 단위**로 LONG의 해당 월 섹션(`## 2026-06`)에 병합하고 MIDDLE에서 제거한다.
   - **지금도 유효한 결정과 프로젝트 궤적만** 1~2문단으로 남긴다. 그 외는 버린다.
3. **LONG 보호**: LONG은 자동 삭제하지 않는다. 300줄을 넘으면 사용자에게 정리를 **제안만** 한다.
4. **결과 보고**: "이동 n건, RECENT x줄 → y줄" 형식으로 각 계층의 변화를 보고한다.

## 단독 호출

"메모리 정리해줘" 단독 요청에도 위 규칙 그대로 실행한다 (오늘 엔트리 추가는 하지 않는다 — 그것은 day-close의 일이다).

## 완료 기준

- [ ] RECENT에 7일 초과 엔트리가 없다
- [ ] MIDDLE에 30일 초과 섹션이 없다
- [ ] LONG은 삭제된 내용 없이 병합만 되었다
- [ ] 이동·줄수 변화가 보고되었다
