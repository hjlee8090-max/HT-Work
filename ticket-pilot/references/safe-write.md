# 안전 저장 · 변경 저널 (Ticket Pilot 공통 규약)

여러 세션이 같은 프로젝트를 동시에 열 수 있다. 이 문서는 `.ticket-pilot/` 아래 파일을 **유실 없이** 쓰고, 누가 언제 무엇을 바꿨는지 **추적 가능하게** 남기는 규약이다. tickets.json·profile.md·memory 3파일·HANDOFF.md를 쓰는 모든 스킬이 이 규약을 따른다.

## 막으려는 사고

위험은 하나다 — **한 번 읽어 오래 들고 있다가 파일 전체를 덮어쓰는 것.** 그 사이 다른 세션이 추가한 티켓은 소리 없이 사라진다. 세션이 길수록 손에 든 사본이 낡으므로, 사고는 시간이 지날수록 잦아진다.

지문이 뚜렷하다: 대부분의 티켓이 바이트 단위로 같은데 최근에 생긴 몇 건만 없다. 병합 실패가 아니라 낡은 사본의 전체 덮어쓰기다.

두 장치로 막는다. **안전 저장**(유실 방지)과 **저널**(추적·복구).

---

## 1. 안전 저장 절차

### 1-1. 로드 시 (세션에서 파일을 처음 읽을 때)

1. 파일을 읽고 `updated_at`을 **로드 기준값**으로 기억한다. 티켓 ID 집합도 함께 기억한다.
2. **저널 대조**를 수행한다 (2-3). 유실이 감지되면 어떤 저장보다 먼저 보고한다.

### 1-2. 저장 시 — 예외 없이 모든 쓰기에 적용

**읽은 사본으로 파일 전체를 덮어쓰지 않는다.** 순서를 지킨다:

1. **재읽기** — 쓰기 직전에 파일을 다시 읽는다.
2. `updated_at`이 로드 기준값과 같다 → 4로 간다.
3. 달라졌다 → 다른 세션이 썼다. **중단하지 말고 병합한다** (1-3).
4. **축소 금지 검사** — 저장할 티켓 ID 집합이 재읽기한 파일의 ID 집합을 **전부 포함**하는지 확인한다. 하나라도 빠지면 **저장하지 않는다.** 빠진 ID를 보고하고 멈춘다.
   - 티켓은 삭제되지 않는다 — 반려도 `rejected`라는 status다. **ID가 줄어드는 저장은 언제나 사고다.**
5. 저장하고, 같은 턴에 **저널에 기록한다** (2).

### 1-3. 병합 규칙 — 티켓 ID 단위

재읽기한 파일을 **바탕**으로 삼고 내 변경만 얹는다. 파일 쪽을 내 사본으로 갈아치우지 않는다.

| 상황 | 처리 |
|---|---|
| 파일에만 있는 ID (내 사본에 없음) | 다른 세션의 신규 티켓 — **그대로 보존** |
| 내 사본에만 있는 ID (파일에 없음) | 다른 세션이 유실시킨 것 — **되살리고 보고** |
| 양쪽에 있고 나만 바꿨다 | 내 변경 적용 |
| 양쪽에 있고 상대만 바꿨다 | 파일 쪽 유지 (건드리지 않는다) |
| 양쪽에 있고 **둘 다 바꿨다** | **그 티켓만 보류** — 저장하지 않고 필드 차이를 보고해 선택을 받는다 |

- 병합했으면 보고에 1줄 남긴다: `병합: 다른 세션 변경 n건 보존, 내 변경 m건 적용`.
- 충돌 티켓이 있어도 나머지는 저장한다 — 충돌 1건이 전체를 막지 않는다.
- 상대가 바꾼 필드와 내가 바꾼 필드가 겹치지 않아도 **같은 티켓이면 충돌로 본다.** 필드 단위 자동 병합은 하지 않는다 (status와 steps처럼 서로 얽힌 필드가 있다).

### 1-4. 산문 파일 — profile.md · memory 3파일 · HANDOFF.md

티켓 ID 같은 단위가 없으므로 **절 단위**로 같은 원칙을 적용한다:

1. 쓰기 직전 다시 읽는다.
2. 내가 읽은 뒤 내용이 달라졌으면 — 내 편집을 **현재 파일 위에 다시 적용**한다. 들고 있던 사본으로 덮어쓰지 않는다.
3. **축소 금지**: 결과가 현재 파일보다 짧아지는데 그게 의도한 압축(day-close 2절)이 아니면 저장하지 않고 보고한다.
4. **"같은 내용이라 덮어썼다"는 판단을 하지 않는다** — 같은 내용이면 쓸 이유도 없다. 이 판단은 가드를 무력화하는 가장 흔한 경로다.

## 2. 변경 저널 `.ticket-pilot/journal.ndjson`

### 2-1. 형식

JSON 한 줄 = 변경 1건. **덧붙이기(append)만 한다 — 기존 줄을 고치거나 지우지 않는다.** 덧붙이기는 덮어쓰기와 달리 동시에 일어나도 서로를 지우지 않는다. 이것이 저널이 tickets.json보다 튼튼한 이유다.

```
{"at":"2026-08-03T11:24:07+09:00","session":"a3f9","actor":"ticket-create","op":"create","ticket":"T-018","note":"결제 실패 안내 문구 보강"}
{"at":"2026-08-03T11:26:12+09:00","session":"a3f9","actor":"ticket-run","op":"status","ticket":"T-018","from":"approved","to":"in_progress"}
{"at":"2026-08-03T12:02:44+09:00","session":"a3f9","actor":"day-close","op":"write","file":"profile.md","note":"R-05 승격"}
```

| 키 | 값 |
|---|---|
| `at` | ISO 8601, tickets.json과 같은 형식 |
| `session` | 이 세션의 4자리 ID. **세션에서 처음 저널을 쓸 때 임의로 만들고 그 세션 내내 재사용한다** |
| `actor` | 쓴 주체 — `project-setup` · `ticket-create` · `ticket-run` · `day-close` · `session-handoff` · `board` |
| `op` | `bootstrap` · `create` · `status` · `edit` · `result` · `comment` · `write` · `restore` |
| `ticket` | 대상 티켓 ID (티켓 대상이 아니면 생략) |
| `file` | 대상 파일명 (티켓이 아닌 파일 변경일 때) |
| `from`·`to` | status 변경 시 이전·이후 상태 |
| `note` | 한 줄 요약 (제목·승격 규칙 등) |

- 티켓 여러 건을 한 번에 바꿨으면 **티켓당 1줄**씩 쓴다. 한 줄에 몰지 않는다 — 대조가 안 된다.
- 저널은 기록이지 원본이 아니다. **원본은 여전히 tickets.json이다.**

### 2-2. 부트스트랩 — 파일이 없을 때

`journal.ndjson`이 없으면 만들고 첫 줄에 현재 상태를 박아 넣는다:

```
{"at":"…","session":"a3f9","actor":"<이 스킬>","op":"bootstrap","note":"기존 티켓 19건 기준선","ids":["T-001","T-002","…"]}
```

이 줄부터 대조가 가능해진다. 저널 없이 쓰던 기존 프로젝트도 이 한 줄로 즉시 편입된다.

### 2-3. 저널 대조 — 로드 시 유실 감지

저널을 재생해 **있어야 할 티켓 ID 집합**을 만든다 (마지막 `bootstrap`의 `ids` + 그 이후 모든 `create`·`restore`의 `ticket`). tickets.json의 ID 집합과 비교한다:

- **저널에 있는데 tickets.json에 없다 → 유실이다.** 저장을 시작하기 전에 보고한다:
  `⚠️ T-018·T-019가 저널에는 있으나 tickets.json에 없습니다 (07-30 생성, session b71c). 복구할까요?`
  - 복구는 **사용자 승인 후에만** 한다. 승인하면 되살리고 `op:"restore"`를 남긴다.
  - 저널에는 티켓 전문이 아니라 ID·제목만 있다. 본문 복구는 git 히스토리(`.ticket-pilot/`은 커밋 대상이다)에서 해당 시점 tickets.json을 꺼내는 것이 정확하다 — 저널은 **무엇이 없어졌는지**를 알려주는 장치다.
- **저널에 없는데 tickets.json에 있다** → 저널을 안 쓰는 경로(보드 직접 저장·손편집)로 생긴 것이다. `op:"create"` 1줄을 보충해 저널을 따라잡히고 넘어간다. 사고가 아니다.

### 2-4. 크기 관리

1000줄을 넘으면 day-close에서 **가장 오래된 500줄을 `journal.<YYYY-MM>.ndjson`으로 옮긴다.** 삭제하지 않는다. 옮긴 뒤 현재 저널 첫 줄에 `bootstrap`을 새로 써서 대조 기준선을 유지한다.

## 3. 적용 지점

| 스킬 | 지점 |
|---|---|
| project-setup | 워크스페이스 생성 시 journal.ndjson 생성 (`op:"bootstrap"`) |
| ticket-create | A-5 신규 저장 · B-2 보드 반영 저장 |
| ticket-run | 3단계 선점 저장 · 5단계 완료 기록 |
| day-close | profile.md · memory 3파일 · CLAUDE.md 블록 · 저널 크기 관리 |
| session-handoff | HANDOFF.md 저장 · 소비 마킹 |
| board.html | [저장] 시 병합 (저널은 쓰지 않는다 — 파일 핸들이 tickets.json 하나뿐이다. 다음 스킬 호출이 2-3의 보충 규칙으로 따라잡는다) |
